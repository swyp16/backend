# 0003. 쓰기는 JPA, 복잡한 조회는 jOOQ

- 상태: 확정
- 날짜: 2026-11-26
- 이슈: 14-37

## 맥락

11/25 회의록의 ORM 항목은 "JPA QueryDSL? jOOQ?"로 남아 있어 무엇을 쓸지 분명하지 않았다.

## 결정

- 생성·수정·삭제는 JPA로 한다.
- 단순 조회는 Spring Data의 메서드 이름 쿼리로 한다.
- 조인·집계·동적 조건이 필요한 조회는 jOOQ로 한다.
- QueryDSL은 쓰지 않는다.
- `@Query`(JPQL·native)는 쓰지 않는다. CI가 막는다([0006](0006-ci-enforced-code-rules.md)).
- jOOQ 코드는 **Flyway 마이그레이션 SQL을 jOOQ가 직접 해석해** 생성한다(DDLDatabase, jOOQ 공식 Gradle 플러그인 `org.jooq.jooq-codegen-gradle`, Boot가 관리하는 jOOQ 버전). 빌드에 DB가 필요 없다.

## 검토한 대안

| 대안 | 탈락 이유 |
|---|---|
| JPA + QueryDSL | Boot가 관리하는 원본(`com.querydsl` 5.1.0)은 2024-01 이후 릴리스가 없다. 유지되는 포크(OpenFeign 7.x)는 Boot 관리 대상이 아니라 버전과 APT 설정을 직접 맞춰야 한다 |
| jOOQ만 | 단순 쓰기에도 SQL을 다 써야 하고, 변경 감지·낙관적 락 같은 JPA의 편의를 잃는다 |
| JPA만 (JPQL) | 모금액 합계, 상태별 개수 같은 집계 쿼리가 문자열이라 컴파일 시점에 검증되지 않는다 |

**코드 생성 방식**

| 대안 | 탈락 이유 |
|---|---|
| 빌드 중 임시 DB(Testcontainers + Flyway) | 실제 스키마와 정확히 같지만, 모든 빌드에 Docker가 필요하다. 프론트가 mock 서버를 빌드할 때도 마찬가지다 |
| 떠 있는 DB에 접속 | DB가 최신 마이그레이션 상태로 떠 있어야 하고, 사람마다 결과가 달라질 수 있다 |
| 생성물 커밋 | 재생성을 잊으면 스키마와 어긋나고, 4명이 동시에 작업하면 충돌이 잦다 |
| 생성 안 함(문자열 DSL) | 타입 검증이 없어 jOOQ를 쓰는 이유가 대부분 사라진다 |

## 트레이드오프

- **얻는 것:** 쓰기는 JPA로 짧게 쓰고, 집계와 목록은 SQL에 가까운 타입 안전 쿼리로 쓴다. jOOQ 버전은 Boot가 관리한다.
- **잃는 것:**
  - 팀이 데이터 접근 기술 두 가지를 익혀야 한다.
  - 같은 트랜잭션에서 JPA로 쓴 뒤 jOOQ로 읽으면 flush 전 변경이 보이지 않는다. 쓰기 직후 같은 트랜잭션에서 jOOQ로 조회할 때는 먼저 flush해야 한다.
  - 메서드 이름 쿼리로 안 되는 조회는 JPQL 한 줄짜리라도 jOOQ로 써야 한다.
  - SQL 해석 방식이라 PostgreSQL 전용 문법 일부는 해석하지 못할 수 있다. 그런 구문은 `[jooq ignore start]`/`[jooq ignore stop]` 주석으로 건너뛴다. 생성된 타입이 실제 DB와 다르게 해석되면 Testcontainers 테스트에서 드러난다.

## 후속 확인

- 해석이 반복해서 막히면 빌드 중 임시 DB 방식으로 바꾸고 새 ADR을 쓴다.
