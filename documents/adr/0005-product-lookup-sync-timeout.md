# 0005. 상품 조회는 동기, 시간 초과 시 직접 입력

- 상태: 확정
- 날짜: 2026-11-26
- 이슈: 14-37

## 맥락

상품 링크를 붙이면 상품명·가격·이미지를 채운다(FEAT-012). 조회는 상품 조회 서비스(별도 프로젝트)가 REST API로 제공하고, 백엔드는 그 API를 부른다. 조회 서비스의 특성은 다음과 같다(2026-11-24 기준, 프로젝트 진행에 따라 바뀔 수 있다).

- 느린 쇼핑몰은 첫 조회가 10초를 넘는다(네이버 9~14초). 이어지는 조회는 더 빠르다.
- 오래 걸리면 1분이 넘는다.
- 바쁘거나 조회할 수 없는 상태면 즉시 그렇다고 응답한다.

## 결정

- 백엔드는 상품 조회 서비스 API를 동기로 호출하고, **15초**(설정값)를 넘으면 직접 입력으로 넘긴다.
- 응답은 항상 200이고 `result`는 `FOUND` 또는 `MANUAL`이다.
- 조회 서비스가 바쁘거나 조회할 수 없다고 응답하면 기다리지 않고 바로 `MANUAL`이다.
- 기다리는 요청이 서버 스레드를 점유하지 않도록 가상 스레드를 켠다.

## 검토한 대안

| 대안 | 탈락 이유 |
|---|---|
| 비동기(접수 → 폴링) | 1분이 넘는 조회도 결과를 받을 수 있다. 대신 엔드포인트 2개, 작업 상태 저장, 프론트 폴링이 필요하다 |
| 10초 제한 | 네이버 첫 조회(9~14초)가 자주 직접 입력으로 빠진다 |

## 트레이드오프

- **얻는 것:** API 1개, 프론트 분기 1개로 끝나고 작업 상태를 저장하지 않는다. 기획의 "실패하면 직접 입력으로 바로 전환"과 맞는다.
- **잃는 것:** 15초를 넘긴 조회는 성공해도 결과를 쓰지 못한다.
- **보완:** 늦게 끝난 결과는 URL별로 서버 메모리에 하루 동안 캐시한다. 같은 링크를 다시 붙이면 바로 채워진다. 인스턴스별 캐시라 재배포하면 비워진다.

## 후속 확인

- API 계약(경로, 응답 코드, 오류 종류)은 상품 조회 서비스에서 정한다.
