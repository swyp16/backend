# 0006. 기계로 판정할 수 있는 규칙은 CI가 막는다

- 상태: 확정
- 날짜: 2026-11-26 (같은 날 셋업 중 리뷰를 반영해 SQL·시간 규칙을 Checkstyle에서 ArchUnit으로 옮겼다)
- 이슈: 14-37

## 맥락

엔티티 외부 공개, 컨트롤러의 비즈니스 로직, 의존 순환 같은 Spring 금지 규칙은 리뷰에서 놓치기 쉽다.

## 결정

기계로 판정할 수 있는 규칙은 CI에서 빌드를 실패시킨다. 형식은 Checkstyle이, 코드 의미는 ArchUnit이 막는다.

**Checkstyle 14.4.0** (경고가 하나라도 있으면 실패)
- 들여쓰기 4칸
- 미사용 import, 와일드카드 import 금지

**ArchUnit 1.5.1**
1. 요청·응답 DTO는 엔티티에 의존하지 않는다.
2. 컨트롤러는 Repository와 엔티티에 직접 의존하지 않는다.
3. 컨트롤러에 `@Transactional`을 붙이지 않는다(클래스, 메서드).
4. 도메인 패키지(`kr.moadream.<도메인>`) 사이에 순환이 없다. 도메인 안의 하위 패키지끼리는 검사하지 않는다.
5. `@Query`, `@NativeQuery`를 쓰지 않는다([0003](0003-jpa-write-jooq-read.md)).
6. 문자열을 받는 jOOQ API(`@PlainSQL`)를 부르지 않는다. 생성 코드(`kr.moadream.jooq`)는 제외한다.
7. `LocalDateTime`을 쓰지 않는다. 시간은 `Instant`로 다룬다. 생성 코드는 제외한다.

**검토했지만 넣지 않은 규칙**

| 대상 | 제외 이유 |
|---|---|
| SQL 정규식 규칙 두 개(`dsl.fetch…(` 호출 금지, `"select …"` 문자열 금지) | 타입 안전한 `dsl.fetchOne(TABLE, 조건)`과 `"Update completed"` 같은 로그 문자열까지 막는다. 반대로 `where("name = '" + name + "'")` 같은 SQL 주입은 통과시킨다. ArchUnit의 `@PlainSQL` 규칙으로 바꿨다 |
| `LocalDateTime` Checkstyle 규칙 | 필드와 지역 변수만 보고, record 구성 요소·파라미터·반환 타입을 놓친다. ArchUnit 의존 규칙으로 바꿨다 |
| 허용 목록을 동결하는 래칫 테스트 | 새 코드라 동결할 기존 위반이 없다 |
| 모듈 경계 테스트 | 단일 모듈이다 |
| JPA 연관관계 전면 금지 | 4주 일정에서 팀 학습 비용이 크다 |

## 검토한 대안

| 대안 | 탈락 이유 |
|---|---|
| 리뷰(사람·봇)로만 지키기 | 누락이 생기고, 리뷰어가 기계적인 지적에 시간을 쓴다 |

## 트레이드오프

- **얻는 것:**
  - 리뷰어는 판단이 필요한 부분만 본다.
  - 봇이 놓쳐도 규칙은 지켜진다.
  - 애너테이션과 타입으로 판정해서 정규식처럼 오탐하거나 놓치지 않는다.
- **잃는 것:**
  - 예외가 필요하면 규칙을 고쳐야 한다. PR에서 논의한다.
  - `@Query` 금지 때문에 메서드 이름 쿼리로 안 되는 조회는 모두 jOOQ로 쓴다.
  - `LocalDateTime` 금지로 시간대 처리는 일관되지만, 화면 표시 단계에서 한국 시간으로 변환해야 한다.
  - `JdbcTemplate`처럼 jOOQ 밖에서 SQL 문자열을 실행하는 경로는 막지 않는다. CodeRabbit 지침으로 본다.

## 후속 확인

- 판단이 필요한 규칙(책임 과다, 불필요한 추상화, 이름 일관성)은 리뷰 봇이 본다([0007](0007-coderabbit-pr-review.md)).
