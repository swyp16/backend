# 0002. DB는 PostgreSQL

- 상태: 확정
- 날짜: 2026-11-26
- 이슈: 14-37

## 맥락

관리형 DB를 쓰기로 했지만(11/25 회의) DB 엔진은 정하지 않았다. 4주 동안 백엔드 4명이 마이그레이션을 계속 추가한다.

## 결정

- PostgreSQL을 쓴다.
- 메이저 버전은 운영 DB를 만들 때 고르는 버전으로 하고, Testcontainers 이미지를 같은 버전으로 고정한다. 18을 제안한다. 19.0은 2026-09에 나와 운영 환경에서 지원되는지 확인해야 한다.

## 검토한 대안

| 대안 | 탈락 이유 |
|---|---|
| MySQL | DDL이 암묵적으로 커밋되어, 마이그레이션이 중간에 실패하면 수동으로 복구해야 한다 |
| MariaDB | MySQL과 같은 이유 |

## 트레이드오프

- **얻는 것:**
  - DDL도 트랜잭션 안에서 실행되어, 트랜잭션으로 도는 Flyway 마이그레이션은 중간에 실패해도 통째로 롤백된다. `CREATE INDEX CONCURRENTLY`처럼 트랜잭션 밖에서 도는 구문은 예외라, 실패하면 남은 객체(INVALID 인덱스 등)를 확인한다.
  - 부분 인덱스 같은 제약을 DB에서 걸 수 있다(예: 진행 중인 펀딩에만 유일 조건).
- **잃는 것:** MySQL 계열에 익숙한 팀원은 익혀야 할 것이 있다(identity/sequence, `ON CONFLICT`, 대소문자 규칙). Hibernate·jOOQ·Flyway는 모두 지원해서 도구 쪽 제약은 없다.

## 후속 확인

- 테스트 DB와 운영 DB의 버전이 다르면 동시성 결함이 테스트에서 숨는다. 운영 DB 버전이 정해지면 Testcontainers 이미지 태그를 그 버전으로 맞춘다.
